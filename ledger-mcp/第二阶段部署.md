# 第二阶段：ChatGPT 准备账单，本人确认保存

状态：本地实现和自动测试通过；尚未上传本次更新、执行新 SQL、部署新版函数或测试真实新增。此前线上查询已由用户验证成功。

## 使用方式

在 ChatGPT 说“今天午餐 32 元，餐饮”。工具准备草稿，返回金额、名称、分类、北京时间日期和确认链接。打开链接，使用记账账号登录，核对后点击“确认保存这笔账单”。然后回到 ChatGPT 让它检查是否已保存。原 2.2 记账本会看到这笔账单。

聊天中的“已确认”不是服务端授权凭据；MCP 不提供最终保存工具。确认页访问必须是该账号的普通登录会话，OAuth 会话不能调用保存函数。不要让代理代用户点击确认。工具 annotations 只是提示，不是安全边界，参考 https://developers.openai.com/plugins/reference 。

## 文件与部署顺序

1. 解压本次升级包。根目录应为 `ledger-mcp` 文件夹及 `expense-confirm.html`、`expense-confirm.js`、`oauth-consent.html`、`oauth-consent.js`、`oauth-consent.css` 五个文件。上传这些内容到 GitHub 仓库根目录，建议新分支 `ledger-confirmed-expenses` 创建 PR 后检查再合并。原 index.html、PWA 文件不会被覆盖。不要上传 ZIP 本身。
2. 在 Supabase SQL 编辑器执行 `ledger-mcp/supabase/05-confirmed-expenses.sql` 全文，不替换占位符。它建立独立草稿表及 3 个固定用途函数；新增流程默认关闭。不要重跑 01～04 旧脚本。
3. 用升级包中的 `ledger-mcp/supabase/functions/ledger-mcp/index.ts` 全文替换已部署的 ledger-mcp 函数并部署。Verify JWT with legacy secret 保持关闭；函数仍验证签名、issuer、audience、账号和客户端。URL、Client ID、Secret、认证方法 client_secret_post、Auth Hook 都保持现有配置。
4. 确认 GitHub Pages 发布成功。新页面 `https://taba91659-hub.github.io/wangye/expense-confirm.html` 不带草稿标识打开时应提示从 ChatGPT 提供的链接进入，不能直接保存。
5. 执行 `ledger-mcp/supabase/06-enable-drafts.sql`，结果两列 enabled / drafts_enabled 均应为 true。这是实际启用步骤；在确认页发布前不要执行。
6. 在 ChatGPT 刷新应用工具列表（准确菜单按当前界面确认）。应看到原来的 list_expenses、summarize_expenses，加上 prepare_expense、get_expense_draft。不要删除 OAuth 客户端或更换密钥。可把应用显示名称改为“我的记账本”，原“只读”名称已经不能完整描述新增草稿能力。

## 验收（需要用户在确认页亲自操作）

- 指定一笔真实打算记入的账单，核对四个字段后再点保存，不凭空写测试账单。
- 尚未确认时，原记账本总额不变；确认后恰好多一笔。
- 同一链接重复点击保存，只返回原记录 ID，不新增第二笔。
- 换另一账号无法读/保存草稿；15 分钟未确认的草稿不能保存。
- 原来的查询、分类统计及 2.2 页面继续正常使用。
- 每次独立记账意图用新 UUID；同一次请求重试沿用 request_id。相同 request_id 搭配不同内容会拒绝。不同 request_id 的相同内容视为不同草稿，仍需分别本人确认。

## 规则

人民币大于 0、最多两位小数、上限 999999999；名称去首尾空格后 1～60 字且无控制字符；类别只能为餐饮/购物/交通/娱乐/其他；日期必须真实且在 2000-01-01 至北京时间今天之间。缺失/含糊字段让 ChatGPT 先询问，不静默猜测。该版按天记账，数据库时间为北京时间所选日期 00:00。

草稿不可编辑，显示内容即保存内容；更正需要生成新草稿。最多 30 份同时有效的待确认草稿。账号和客户端每次从已验证身份及绑定配置核对，不接受调用者指定 user_id。数据函数只处理固定表与字段，没有任意 SQL。

事务和行锁保证同一草稿的插入与结果记录同时成功，重试返回原结果。已完成草稿保留作为防重复记录；即使用户之后从原网页删除该账单，重试也不会重新创建。安全定义者函数只在服务器执行固定插入，仍保留原表禁止 OAuth 写入的限制。

## 停用与风险范围

执行 `07-disable-drafts.sql` 立即关闭准备草稿和确认保存，现有查询不受影响。执行原 `03-disable.sql` 则停用整个连接。已创建的账单不会自动撤销。

确认页不持久化登录令牌，姓名等内容用 textContent 渲染，草稿 ID 放在 URL 的 # 后面并要求登录验证。链接本身不是保存权限。密码和密钥不得放进聊天、仓库或日志。

本地测试使用独立 PostgreSQL/PGlite、真实 MCP SDK + 模拟网络和页面事件测试。尚未在生产环境完成本阶段新增、浏览器视觉检查或真实并发压力验证。不能将本地通过表述为线上接入已完成。
