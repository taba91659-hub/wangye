# ChatGPT 只读记账连接：待部署草稿

目前只有本地代码和测试，尚未完成线上授权、部署或真实账单查询。原 2.2 首页、预算、离线文件都不改动。第一阶段只支持查询自己的账单与统计支出。

## 采用的方案

ChatGPT 自定义 MCP → Supabase Edge Function → 使用本人 OAuth 登录身份查询数据库。数据库仍通过 auth.uid() 隔离账号，并额外校验指定的 OAuth 客户端。服务端和前端均不使用 service_role key 或个人数据库密码。

OAuth 的 scopes 本身不限制数据库权限，因此 SQL 额外阻止 OAuth 会话添加、修改、删除账单，阻止访问预算和存储文件。其他普通网页登录会话按原策略继续工作。

参考：[OpenAI OAuth 接入](https://developers.openai.com/plugins/build/auth)、[Supabase MCP](https://supabase.com/docs/guides/ai-tools/byo-mcp)、[OAuth 数据权限](https://supabase.com/docs/guides/auth/oauth-server/token-security)。

## 用户需要亲自做的部分

- 确认哪一个记账账号属于自己。
- 在官方登录页输入密码、验证码；在专用配置框粘贴客户端密钥。
- 批准将自己的账单读取权限授予这个 ChatGPT 连接。
- 真实查询后对照记账本核对金额。无需把密码或账单截图公开。

## 验收

- 不登录访问 MCP：返回 401，附 OAuth 提示；元数据可以公开。
- ChatGPT 中应只有 list_expenses 与 summarize_expenses 两个工具。
- 询问“本月餐饮花了多少钱？”：中国时区、月初包含、下月月初不包含；结果对照记账本。
- 查询明细有分页，不把第一页当总额；金额在数据库用精确小数汇总。
- 用另一个账号登录不得读取账单；请求添加账单时不能执行。
- 验证原 2.2 网页正常登录、查询和预算功能。需要真实新增/删除测试记录时，先由用户指定测试记录。
- OAuth 过期后刷新、重新连接均需真实测试。当前授权页遇到“已有授权记录”会停止自动跳转；需撤销旧授权再连接，这是已知限制。

## 停用

执行 `supabase/03-disable.sql` 即可停止连接读取，再在 ChatGPT 断开连接。保留限制策略；不要为停用而删除原 RLS。Hook 对未绑定连接原样返回，普通网页登录继续按原逻辑工作。
